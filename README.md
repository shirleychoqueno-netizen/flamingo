# flamingo

**Flame Learning & Analysis in Microgravity: INsights for Gravity-Off missions**

[Public application](https://flamingo.houston-groq-proxy.workers.dev/) · [Research API](https://houston-groq-proxy.houston-groq-proxy.workers.dev/health)

This collaboration checkout contains the published React/Vite frontend, its source data snapshots, the existing Cloudflare research Worker/proxy and tests. The API supports live hybrid/semantic retrieval and exact source-row comparison. The public research guide uses source-backed discovery; paid GPT/Groq generation is disabled. The backend's historical name contains "groq", but no provider key is needed for the normal published experience.

## Requirements

- Git; a GitHub account with collaborator access to push changes.
- Node **24.x**, tested with **24.22.1**; .nvmrc and .node-version pin it.
- **pnpm 11.25.0** for the frontend, pinned in package.json.
- npm bundled with Node for the isolated Worker package. Use worker/package-lock.json with npm ci.
- Existing Cloudflare account access only for deployment or production remote bindings. Tests and the default lexical local Worker need no model key.

If pnpm is unavailable, install the pinned version with `npm install --global pnpm@11.25.0` or use your existing package-manager setup. Do not silently upgrade dependencies or replace the lockfiles.

## Layout

```text
src/                       React interface and catalog metadata
public/                    NASA media, PDFs and per-investigation source rows
scripts/                   frontend verification and repository checks
wrangler.toml              existing flamingo static Worker; assets = dist
worker/src/                research API, provenance and provider adapters
worker/src/generated/      canonical retrieval corpus (tracked)
worker/demo/               technical workbench and recorded evaluation
worker/fixtures/           public source fixtures for offline tests
worker/test/               backend tests
worker/wrangler.toml       existing production research API configuration
worker/wrangler.dev.toml   local-only keyword search; generation disabled
docs/                      integration, source origin and collaboration notes
```

The large remote NASA collection is referenced, not stored in Git. Included source snapshots are small enough for ordinary Git. Keep the canonical retrieval-corpus.json tracked; it is required to run the backend. demo-assets.mjs is regenerated by the included script and ignored.

```text
git clone https://github.com/Maran-sjmh/flamingo.git

```

## Install from a fresh clone

```text
pnpm install --frozen-lockfile
pnpm run worker:install
```

The root pnpm workspace explicitly contains only this frontend. worker/ has its own npm lockfile. This preserves the tested dependency sets without converting the live backend to another package manager.

## Run the frontend

```text
pnpm dev
```

Open **http://localhost:5173**. By default it uses the existing deployed API. That API allows the exact http://localhost origin with optional port; http://127.0.0.1 is a different browser origin.

Only VITE_API_BASE_URL is a public frontend setting. To use the local Worker instead, create ignored `.env.local` containing:

```dotenv
VITE_API_BASE_URL=http://localhost:8787
```

Restart Vite after changing that file. Never place a model key in a VITE_ variable.

## Run the local research/Groq-compatible proxy

In a second terminal:

```text
pnpm run worker:dev
```

The API listens on http://127.0.0.1:8787; the frontend points to it as http://localhost:8787. Health is at /health; evidence routes are /v1/rag and /v1/compare. The local config deliberately has no Workers AI/Vectorize binding and ENABLE_SEMANTIC_SEARCH=false. Search mode auto reports lexical fallback. Reuse the published API for semantic discovery, or arrange explicit Cloudflare remote-binding access with the backend owner.

The local proxy still reads the existing public Firestore source cells for comparisons, so those comparisons need network access. Backend unit tests use fixtures and make no real provider calls. With the local Worker running, `pnpm run test:local-proxy` checks keyword retrieval and a read-only public-source comparison without model calls.

Groq and OpenAI adapters remain in worker/src for compatibility. They are disabled by default. The worker/.env.example inventories variable names without values. Optional local secrets go in ignored worker/.dev.vars, based on worker/.dev.vars.example. Merely adding a key does not enable generation; preserve the flags until the owner authorizes a separately scoped evaluation/deployment. A previous private evaluation budget does not authorize new calls in this checkout.

## Deploy manually to the existing frontend

After installing both packages and signing in through the existing Worker CLI:

```text
node worker/node_modules/wrangler/bin/wrangler.js login
pnpm build
pnpm run deploy:check
pnpm run deploy
```

Root wrangler.toml keeps `name = "flamingo"`, the existing account and `assets.directory = "dist"`. Deployment updates the same Worker and preserves https://flamingo.houston-groq-proxy.workers.dev/. It does not create a replacement domain or automatically redeploy the API.

Backend deployment is separate:

```text
npm --prefix worker run dry-run
npm --prefix worker run deploy
```

Its configuration retains the existing API name, Vectorize index, rate-limit bindings and disabled paid-generation gates. A backend deployment requires permissions for its configured resources. Review concurrent remote changes before deploying.

## Secrets

No provider key belongs in Git, frontend JavaScript, build output or shared Drive packages. .env.example files contain names only. For any separately approved deployed provider integration, configure the secret on the **API Worker**, not on the static frontend:

```text
node worker/node_modules/wrangler/bin/wrangler.js secret put GROQ_API_KEY --config worker/wrangler.toml
node worker/node_modules/wrangler/bin/wrangler.js secret put OPENAI_API_KEY --config worker/wrangler.toml
```

These are reference commands, not setup steps required for the current demo. Secret changes can deploy a new Worker version. Never paste values into chat, commit them or put them in CLI arguments. Build-time secrets and runtime secrets are different settings in Cloudflare.

## Connect GitHub to the existing Cloudflare Worker

The repository must exist on GitHub with main pushed. Creating a repository or editing this README does not itself connect Workers Builds.

1. In Cloudflare, open **Workers & Pages → flamingo → Settings → Builds → Connect**.
2. Choose GitHub. The repository owner authorizes the Cloudflare GitHub App for the new repository. Confirm the account and repository.
3. Use production branch **main** and repository root **/**.
4. Set Node to **24.22.1** and pnpm to **11.25.0**. The checked-in version files/packageManager pin those versions.
5. Set **SKIP_DEPENDENCY_INSTALL=1** as a build variable so both package installs are explicit and reproducible.
6. Use this build command:

   ```text
   pnpm install --frozen-lockfile && npm --prefix worker ci && pnpm test && pnpm run worker:test && pnpm build
   ```

7. Use this deploy command:

   ```text
   pnpm run deploy
   ```

8. Keep the Worker's current name/domain. Do not create a new Worker from the repository: connect the existing **flamingo** Worker. Cloudflare checks that the selected Worker name matches wrangler.toml.
9. Keep branch-preview deployments disabled initially. Preview domains are not in the API's exact origin allowlist; plan that behavior separately before enabling them.
10. Push a small approved commit to main and confirm a successful build/deployment and the existing URL. Then merges/pushes to main deploy that same site automatically.

Do not supply OPENAI_API_KEY or GROQ_API_KEY as frontend build variables. Workers Builds manages deployment authorization through its own build token settings. This document does not claim the GitHub App or Builds connection has already been configured.

To automate backend deployment later, configure a **separate** Builds connection for houston-groq-proxy, root directory `worker`, build command `npm ci && npm test && node scripts/build_demo.mjs`, deploy command `npm run deploy`, branch main. Because this repository uses pnpm at the top level and npm inside worker/, set NODE_VERSION=24.22.1 and SKIP_DEPENDENCY_INSTALL=1 there too and install npm dependencies explicitly as shown. Keep the backend packageManager field unset so it does not contradict the top-level version selection. Frontend-only changes do not require a backend deployment; configure watch paths/ownership before enabling that second automation.

## Source and product scope

The published guide performs real semantic discovery and source-backed navigation; free-form public generation remains off. The corpus contains 25 investigations, 6,177 evidence items and 3,152 retrieval fragments. Per-study JSON exposes 2,009 nonblank source rows. Remote references and bibliographic entries are not a claim that all full texts or multi-terabyte media have been downloaded. Original numerical strings and comparability limits must survive visual merges.

Earlier deployment/handoff documents are retained under docs/ as historical context. This README describes this checkout. docs/original-sites-hosting.json preserves the visual team's original Sites identity as a reference, not this repository's active deployment target. No existing Site audience was changed.
